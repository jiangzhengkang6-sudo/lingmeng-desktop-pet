# 桌宠事件协议

## 目的

前端、FastAPI 本地网关和 Godot 桌宠渲染层通过结构化事件通信。模型、语音和工具
只能产生业务结果，不能直接操作 Godot 场景或窗口。

## 地址

- `POST /api/pet/events`：发布一个动作事件。
- `WS /api/pet/events`：Godot 长连接接收动作事件。
- `WS /api/agent/events`：文本 Agent 的会话事件通道。
- Godot 受控资源目录：调试窗口将资源包写入本机目录，由 Godot 进程读取。
- Tauri `preview.json`：调试窗口向 Godot 桌宠同步动作、口型、暂停和窗口尺寸。

事件来源按运行模式分工：

- Agent 回复由 FastAPI `/api/agent/chat` 广播到 WebSocket；前端收到响应后不会再次
  发布同一条 Agent 动作。
- 浏览器调试模式下，前端状态变化通过 `POST /api/pet/events` 发布。
- Tauri 桌面模式下，前端主动选择动作、暂停或播放 TTS 时写入 `preview.json`；
  Agent 动作仍以 WebSocket 广播为准。

## 事件格式

### Agent 客户端消息

```json
{
  "type": "agent.message",
  "request_id": "agent-abc123",
  "session_id": "desktop-pet-demo",
  "message": "你好",
  "language": "zh-CN",
  "rag_collection": "character_knowledge"
}
```

### Agent 服务端事件

服务端会按顺序发送 `agent.status(thinking)`、`agent.response`、`pet.action`
以及 `agent.status(completed)`。发生可解释错误时发送 `agent.error`，每条事件
都带有同一组 `request_id` 和 `session_id`，客户端必须按这两个字段关联请求。

`agent.response.response` 的内容与 `POST /api/agent/chat` 返回结构一致。
`pet.action.action` 的内容与 `WS /api/pet/events` 广播结构一致。

前端 AgentClient 收到 `agent.response` 时会缓存结构化回复，收到同一请求的
`agent.status(completed)` 后才结束 Promise；这样 `pet.action` 一定有机会先被
事件回调消费。调用 `chat(input, onEvent)` 可订阅本次请求的全部有效服务端事件，
其中 `pet.action` 会立即驱动前端动作。若 WebSocket 不可用，客户端会自动回退到
`POST /api/agent/chat`；HTTP 回退只返回最终回复，不产生流式事件。

```json
{
  "type": "pet.action",
  "actionId": "speaking",
  "emotion": "happy",
  "mouthMode": "open",
  "durationMs": 1000,
  "interruptible": true
}
```

`action_id`、`mouth_mode`、`duration_ms` 也接受 snake_case。后端广播时统一输出
snake_case，便于 Godot 端处理。

## 字段约束

- `type` 固定为 `pet.action`。
- `actionId` 必须是 `idle`、`listening`、`thinking`、`speaking`、`working`、
  `success`、`failure`、`refuse`、`sleeping`、`reminder` 之一。
- `mouthMode` 可选，取值为 `closed`、`half-open`、`open`。
- `durationMs` 可选，范围为 `0` 至 `600000`。
- `interruptible` 可选，默认值为 `true`。
- 未知字段、非法动作、非法口型或非法时长会被拒绝。

## 动作打断语义

`interruptible` 描述当前事件启动的动作是否允许后续动作打断。Godot 会先检查
当前动作的锁定状态，再决定是否接受新的非 `idle` 事件；`idle` 始终可以用于回退。

## 资源包同步事件

调试窗口不再创建独立的 Tauri `pet` WebView。资源包通过 Godot 受控目录同步：

```json
{
  "manifest": {
    "schemaVersion": "1.0",
    "name": "character",
    "version": "0.1.0",
    "canvas": { "width": 520, "height": 520, "background": "transparent" },
    "spriteSheets": {},
    "actions": {}
  }
}
```

该同步只在本机使用，不经过 FastAPI。PNG 导入内容会以内嵌数据 URL 传输到
Tauri command，再由 Rust 写入受控目录；导出的 `manifest.json` 仍不会写入
图片数据、绝对路径或临时 URL。

## Godot 预览状态

调试界面运行在 Tauri 桌面模式时，会以原子替换方式写入：
`%LOCALAPPDATA%\LingMengDesktopPet\godot-resource-package\preview.json`。

```json
{
  "action": "speaking",
  "mouthMode": "open",
  "paused": false,
  "size": 320
}
```

`size` 会被 Godot 限制在 `120` 至 `480` 像素，并保持正方形窗口；窗口拖动
结束后的边缘吸附仍由 Godot 负责。该文件只作为本地调试控制通道，不接受外部
自然语言或任意脚本内容。

Godot 收到与当前动作相同且没有新时长的事件时，只更新口型状态，不重新从第一帧
启动动作，避免 WebSocket 与本地预览状态汇合时出现闪回。

Tauri 端对 `preview.json` 的写入按最新状态串行合并；语音能量快速变化时，旧的
口型状态不会在新的状态之后覆盖落盘。

## 运行边界

预览状态写入失败不会影响本地 Canvas 预览或语音功能；Godot 未运行时状态文件
仍可写入，下一次启动会读取最新状态。收到非法状态时直接丢弃。

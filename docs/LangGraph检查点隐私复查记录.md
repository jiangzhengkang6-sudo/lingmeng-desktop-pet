# LangGraph 检查点隐私复查记录

复查日期：2026-11-02  
复查范围：LangGraph 主工作流、`open_file` 审批中断图、SQLite 检查点表和维护接口。

## 一、结论

检查点仅用于本地工作流暂停、恢复和上下文编排；默认仍使用内存检查点，不会默认写入磁盘。检查点中可能出现用户消息、会话标识、记忆摘要、RAG 检索结果和待打开文件路径，因此必须按本地敏感数据处理。

检查点中不存储 API Key、原始人脸图像、原始声纹音频、语音原文之外的凭据，也不会把模型输出直接作为系统命令执行。

## 二、存储位置与默认状态

相关配置：

```env
LANGGRAPH_CHECKPOINT_ENABLED=false
LANGGRAPH_CHECKPOINT_PATH=
LANGGRAPH_APPROVAL_INTERRUPT_ENABLED=false
```

默认行为：

- `LANGGRAPH_CHECKPOINT_ENABLED=false`：使用内存检查点，网关退出后图状态不保留；
- 只有显式设为 `true`：才写入 SQLite；
- 检查点路径默认位于本地数据目录，可通过 `LANGGRAPH_CHECKPOINT_PATH` 覆盖；
- 检查点文件仅由本地网关访问，应用不会主动上传。

## 三、数据库表

当前 LangGraph SQLite 检查点使用以下核心表：

| 表 | 内容 | 隐私说明 |
|---|---|---|
| `checkpoints` | 每个图线程的检查点和元数据 | 包含状态快照和节点步骤 |
| `writes` | 节点执行过程中的通道写入 | 包含节点输出的状态片段 |

不同版本的 LangGraph 可能存在额外表；维护接口会在存在时一并清理。

## 四、主工作流中的数据类别

主工作流状态可能包含：

| 状态字段 | 可能内容 | 敏感级别 | 说明 |
|---|---|---|---|
| `request` | 用户消息、语言、会话标识、来源 | 中/高 | 用户消息属于对话内容 |
| `history` | 当前会话历史消息 | 高 | 仅用于模型上下文 |
| `identity` | 身份状态、适配器名称、权限标记 | 中 | 不包含原始人脸或声纹样本 |
| `memories` | 本地长期记忆记录 | 高 | 仅主人身份可读取 |
| `persona` | 当前人格配置 | 低 | 不包含凭据 |
| `sources` / `references` | RAG 来源和检索命中 | 中 | 可能包含本地文档片段 |
| `tool_plan` | 工具名、参数、会话标识 | 中 | 参数仍受工具白名单校验 |
| `tool_result` | 工具执行结果、错误码、审计标识 | 中 | 不包含系统权限令牌 |
| `response` | Agent 最终响应 | 中/高 | 可能复述用户或文档内容 |
| `error` | 错误码、错误消息、HTTP 状态 | 低 | 不应包含密钥 |

## 五、`open_file` 审批中断图中的数据类别

审批中断图状态包含：

| 状态字段 | 可能内容 | 敏感级别 | 说明 |
|---|---|---|---|
| `request` | 工具名、文件路径、会话标识、幂等键 | 中 | 文件路径属于敏感本地元数据 |
| `call_id` | 稳定工具调用标识 | 低 | 相同幂等键会复用 |
| `pending_result` | 待审批结果、审计标识 | 中 | 不包含文件内容 |
| `final_result` | 批准/拒绝后的结果 | 中 | 成功时仅返回路径和打开状态 |

审批中断负载只包含调用标识、工具名、状态和确认提示，不包含文件正文。

## 六、明确不进入检查点的数据

以下数据不写入 LangGraph 检查点：

- 大模型 API Key；
- 火山引擎 Access Key / Secret Key；
- RTC App Key 等凭据；
- 原始人脸图像、人脸关键点数组和声纹注册音频；
- 任意 shell 命令；
- 未经过 Pydantic 校验的工具参数。

## 七、访问与清理控制

### 访问控制

- 检查点查看和清理接口均要求主人身份；
- 网关只监听 `127.0.0.1`；
- 文件仍位于本机数据目录；
- 检查点摘要接口只返回路径、计数和步骤，不返回用户消息、记忆或文件参数内容。

### 清理方式

接口：

```http
GET /api/langgraph/checkpoints?include_runtime=true
POST /api/langgraph/checkpoints/cleanup
```

默认清理：

```json
{
  "only_completed": true,
  "delete_all": false,
  "vacuum": true
}
```

仅删除已经结束的图线程，仍在等待审批或远程响应的线程会保留。

强制清空：

```json
{
  "only_completed": false,
  "delete_all": true,
  "confirm": "DELETE_ALL",
  "vacuum": true
}
```

注意：删除检查点不会删除 `ControlledToolService` 中独立保存的审批单和审计记录；这些记录用于安全追踪，应通过工具数据保留策略另行处理。

## 八、剩余风险

| 风险 | 影响 | 当前缓解 |
|---|---|---|
| 检查点中包含用户消息或文件路径 | 本地文件被读取后泄露对话或路径 | 默认内存检查点、本地访问、主人权限 |
| 检查点数据库被篡改 | 可能影响恢复行为 | LangGraph 显式类型允许列表；文件仅本地保存 |
| 误删仍在审批的线程 | 用户无法继续审批 | 默认仅清理已结束线程 |
| 旧检查点长期保留 | 增加敏感信息滞留时间 | 提供清理接口；后续可加入维护任务 |

## 九、复查结论

当前检查点设计符合渐进式迁移的隐私要求：**默认不落盘、访问需主人身份、摘要不暴露内容、可按完成状态清理、凭据和生物样本不进入检查点。**

后续如启用自动清理，应避免清理仍在等待用户审批的线程，并在清理前保留审计记录。

# 角色资源包规范（v1.1）

本文档定义当前 Canvas 桌宠预览器使用的本地资源配置格式。它描述资源导入、校验、预览和导出的边界，不包含后端、语音、模型或桌面权限能力。

## 当前范围

- 支持同一资源包中的多动作、多 PNG SpriteSheet。
- 支持 10 个基础动作标识：`idle`、`listening`、`thinking`、`speaking`、`working`、`success`、`failure`、`refuse`、`sleeping`、`reminder`。
- 支持方向行走和可选过渡动作；当前默认角色使用
  `transition-idle-to-walk-front-right` 衔接待机与 `walk-front-right`。
- 每个动作定义帧索引、FPS、循环方式、可打断性、锚点和所属 SpriteSheet。
- 每张 SpriteSheet 独立保存网格、有效帧、空白帧和锚点。
- PNG 通过界面单独导入；JSON 中的 `sheet` / `file` 只记录应匹配的文件名或注册表 key，不包含本地路径。
- 未加载 PNG 时，可先导入 JSON 校对元数据；Canvas 将继续显示占位角色。

## 推荐目录

```text
pet-package/
  manifest.json
  sprites/
    idle.png
    listening.png
    speaking.png
    success.png
  actions/
    idle/
      action.json
    speaking/
      action.json
```

`manifest.json` 是完整资源清单。`action.json` 是单个动作的可交换配置，可用于单独校准一个动作。界面允许一次选择多张 PNG，并按 manifest 中的 `file` 或动作的 `sheet` 绑定。

## SpriteSheet 注册表

新版清单使用 `sprite_sheets` 注册多张表，键名由资源包作者定义，建议使用动作名或稳定的资源名：

```json
{
  "sprite_sheets": {
    "idle": {
      "file": "idle.png",
      "width": 128,
      "height": 64,
      "frame_width": 32,
      "frame_height": 32,
      "columns": 4,
      "rows": 2,
      "frame_count": 8,
      "valid_frame_indices": [0, 1, 2, 3],
      "blank_frame_indices": [],
      "anchor": "bottom-center"
    },
    "speaking": {
      "file": "speaking.png",
      "width": 128,
      "height": 64,
      "frame_width": 32,
      "frame_height": 32,
      "columns": 4,
      "rows": 2,
      "frame_count": 8,
      "valid_frame_indices": [0, 1, 2, 3],
      "blank_frame_indices": [],
      "anchor": "bottom-center"
    }
  }
}
```

动作通过 `sheet` 绑定资源。播放器先按注册表 key 匹配，再按 `file` 文件名匹配：

```json
{
  "actions": {
    "idle": {
      "id": "idle",
      "label": "待机",
      "sheet": "idle",
      "frame_indices": [0, 1, 2, 3],
      "fps": 8,
      "loop": true,
      "interruptible": true,
      "anchor": "bottom-center"
    },
    "speaking": {
      "id": "speaking",
      "label": "说话",
      "sheet": "speaking.png",
      "frame_indices": [0, 1, 2, 3],
      "fps": 12,
      "loop": true,
      "interruptible": true,
      "anchor": "bottom-center"
    }
  }
}
```

当资源包注册了多张 SpriteSheet 时，每个动作必须显式填写 `sheet`。只有一张表时可以省略，播放器会使用该表；没有资源表时仍允许使用占位角色预览。

## 帧编号与网格

帧索引从 `0` 开始，按行优先递增：

```text
0  1  2  3
4  5  6  7
```

对每张 SpriteSheet，以下关系必须成立：

- `columns = floor(image_width / frame_width)`。
- `rows = floor(image_height / frame_height)`。
- `frame_count = columns * rows`。
- `valid_frame_indices` 中的每项必须在 `0` 至 `frame_count - 1` 之间。
- `blank_frame_indices` 中的每项必须在 `0` 至 `frame_count - 1` 之间。
- 有效帧和空白帧不得重叠。
- 动作 `frame_indices` 不得引用空白帧；设置了有效帧列表时，也必须包含在有效帧中。

有效帧列表留空时，编辑器会将全部非空白帧视为有效帧。

## action.json

```json
{
  "schema_version": "1.0",
  "id": "speaking",
  "label": "说话",
  "sheet": "speaking.png",
  "frame_width": 32,
  "frame_height": 32,
  "columns": 4,
  "rows": 2,
  "frame_count": 8,
  "valid_frame_indices": [0, 1, 2, 3],
  "blank_frame_indices": [],
  "frame_indices": [0, 1, 2, 3],
  "fps": 12,
  "loop": true,
  "interruptible": true,
  "anchor": "center"
}
```

导入 `action.json` 后，编辑器会切换到该动作，注册或更新对应的 SpriteSheet 元数据，并恢复网格、帧列表和锚点。若尚未导入同名 PNG，需再选择对应文件。

## 锚点

- `bottom-center`：帧的水平中心对齐画布中心，视觉底部放置在预览基线；这是默认值，适合脚底稳定的角色。
- `center`：帧在画布中心显示；适合检查单帧边界。

动作配置的锚点优先于 SpriteSheet 的默认锚点。

## 导入与导出约定

1. 先导入 manifest 时，编辑器注册其中所有 SpriteSheet；再一次或多次导入对应 PNG。
2. 导入 PNG 时优先按 manifest 的 `file` 精确匹配，找不到时使用文件名创建新的资源注册项。
3. 导入 action 时，使用其 `sheet` 作为资源 key；若该资源不存在，会创建等待 PNG 的元数据项。
4. 清单校验存在错误时不可导出。
5. 导出的公共 JSON 使用 snake_case；应用内部使用 TypeScript 的 camelCase。
6. 配置不保存浏览器临时的 `blob:` 图片地址，也不保存绝对文件路径。
7. 旧版单表 `sprite_sheet` 仍可导入，但新导出统一使用 `sprite_sheets`。
8. 在 Tauri 调试窗口打开独立桌宠后，当前资源包会自动同步；PNG 会转为仅用于
   当前运行会话的内嵌数据 URL，确保两个窗口可以共同读取同一张图片。

## 校验与回退

- 每张表都会独立校验网格、锚点、越界帧、有效帧与空白帧重叠。
- 多表清单中，动作引用不存在的 SpriteSheet 或未填写绑定会显示校验错误。
- 缺少 PNG 时，动作清单仍可校验元数据；播放器对无法渲染的帧显示占位角色。
- 动作本身缺失或没有可播放帧时，播放器按既有规则回退到 `idle`。
- 资源包应先在本地校准器中通过校验，再作为后续正式角色资源使用。

一、项目概述

本项目是一款运行在 Windows 桌面的二次元 AI 桌宠。它不是单一聊天机器人：用户可以通过文本或语音与桌宠对话，桌宠会根据语义切换聆听、思考、说话、不悦等动作；也可以让桌宠查询时间、打开白名单应用、检索授权目录文件、播放音乐、设置本地提醒，并在通过主人声纹验证后访问长期记忆等更高权限能力。

五大设计原则

  • 人格稳定 —— 角色语气、称呼、偏好与禁忌通过系统提示词与 Persona 配置保持一致。
  • 本地优先 —— 配置、调试历史、工具审批、本地状态与密钥尽量保存在用户本机。
  • 权限受控 —— 模型不能直接执行任意命令，工具必须走白名单、Schema 校验、审批与审计。
  • 链路可观测 —— ASR、Agent、TTS、工具、RTC 身份等关键环节均有状态展示或本地历史记录。
  • 可替换服务 —— 语音、模型、身份服务均通过本地网关适配，前端不绑定单一供应商。

二、项目总体流程图

系统采用「用户交互 → 桌面前端 → 本地网关 → 云端能力 / 本地数据」的分层架构。所有云端调用都经由本地 FastAPI 网关代理，密钥永不下发前端；桌宠渲染通过 preview.json 文件协议与 Tauri 解耦。

四、智能体在整个项目中的作用

智能体是整个桌宠的「大脑 + 调度中枢」：它向上承接用户的文本/语音输入，向下驱动 TTS 播报、桌宠动作、口型、受控工具与记忆系统。其职责可以拆成六个方面：

  • 多语言对话理解与生成 —— 接收会话历史、确认记忆、RAG 参考资料、Persona 人设块，用 Qwen / OpenAI 兼容接口生成回复；回复不是自由文本，而是被 JSON Schema 严格约束的结构化对象 { text, language, emotion, action_id, mouth_mode, requires_confirmation, memory_candidates }。
  • 驱动桌宠「表演」 —— action_id 与 mouth_mode 直接映射到 Godot 动作状态机（speaking / thinking / displeased…）与口型开合，让回答与表情、口型同步。模型只能从白名单枚举中选择动作，不能越界。
  • 工具意图规划 —— 语音链路上由本地确定性规划器（voice_tool_planner，纯正则规则、不调用大模型）把「现在几点」「打开记事本」「播放音乐」等明确指令映射到受控工具；参数仍要过身份校验、白名单、审批与审计四道关。文本链路则按配置走远程 Agent 或本地规划。
  • 记忆候选提出者 —— 当用户说出稳定事实或偏好时，Agent 最多提出 3 条记忆候选，但永不自动保存，必须经用户在界面上确认；身份未验证（非主人）时记忆读写整体关闭。
  • RAG 融合与来源呈现 —— 可选地从 Milvus 检索 top-3 片段，以「不可信参考资料」标记注入提示词（防止资料中的指令注入），回复携带 sources 与 rag_status 供前端展示。
  • 可靠性兜底 —— 远程模型超时、返回非法结构或网络故障时，按配置降级到本地 Mock Agent 或直接报错，不伪装成功；网关还会在语音场景下纠正动作（idle → speaking），保证桌宠状态与语音播放一致。

安全定位：智能体本身没有执行权。它能做的只有「说话 + 选择白名单内的动作枚举 + 提议记忆候选」；一切桌面操作都由网关侧的受控工具服务在身份、白名单、审批、审计约束下代为执行。这保证了「模型可被替换、权限不可被绕过」。

LangGraph 伪代码（迁移蓝图）

from langgraph.graph import StateGraph, START, END

class PetState(TypedDict):
    request: dict            # message / language / session_id / source
    history: list            # 会话短期上下文
    identity: str            # unknown / guest / owner_verified
    memories: list           # 已确认记忆（仅 owner）
    persona: dict | None     # 人设配置
    references: list         # RAG 检索片段
    tool_plan: dict | None   # 语音工具规划结果
    response: dict           # 结构化 AgentResponse

g = StateGraph(PetState)
g.add_node("assemble_context",       assemble_context)      # 历史/身份/人设/记忆/RAG
g.add_node("execute_controlled_tool", execute_controlled_tool)
g.add_node("call_remote_agent",      call_remote_agent)     # JSON Schema 结构化输出
g.add_node("mock_fallback",          mock_fallback)
g.add_node("postprocess",            postprocess)           # 记忆候选/动作纠正/写回上下文

g.add_edge(START, "assemble_context")
g.add_conditional_edges("assemble_context", route_voice_tool,
    {"tool": "execute_controlled_tool", "agent": "call_remote_agent"})
g.add_conditional_edges("call_remote_agent", validate_output,
    {"ok": "postprocess", "fail": "mock_fallback"})
g.add_edge("mock_fallback", "postprocess")
g.add_edge("execute_controlled_tool", "postprocess")
g.add_edge("postprocess", END)

app = g.compile()

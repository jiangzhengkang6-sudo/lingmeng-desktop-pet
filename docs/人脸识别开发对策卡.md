# 人脸识别系统开发对策卡

> 适用场景：桌面应用内嵌离线 1:1 人脸验证、本地身份授权
> 技术栈：Tauri v2 + Vue3 + FastAPI + OpenCV (YuNet + SFace)
> 项目：Anime Agent Desktop Pet v0.4.0
> 更新：2026-10-17

---

## 一、方案选型与演进

### 1.1 候选方案对比

| 方案 | 模型 | 特征维度 | 主人/他人间隔* | 体积 | 依赖 |
|------|------|---------|--------------|------|------|
| MediaPipe FaceLandmarker | 几何关键点 | 1434 (478x3) | 0.0086 | 10MB | mediapipe (重) |
| **OpenCV YuNet + SFace** | 检测+识别分离 | 128 | **0.4096** | 37MB | opencv-python |
| InsightFace ArcFace | ArcFace ONNX | 512 | ~0.5+ | ~250MB | onnxruntime + 多依赖 |

* 间隔 = 主人组内最劣相似度 - 他人组内最优相似度，用真实样本（主人3张、他人5张）标定。正值越大越好。

### 1.2 选型结论

**默认方案：OpenCV YuNet 检测 + SFace 身份嵌入**

- 区分度足够（间隔 0.41，阈值 0.45 时误判率极低）
- 依赖轻（仅 opencv-python，打包后 236MB 网关 vs mediapipe 方案 370MB+）
- 纯离线，不需要网络
- 对侧脸、遮挡、低光照敏感（桌面应用正面朝向为主，可接受）
- 128 维特征精度不如 ArcFace，但 1:1 验证场景完全够用

### 1.3 方案切换触发条件

- 几何关键点方案 -> **真实样本标定间隔 < 0.1** -> 切换到 SFace
- SFace 方案 -> 多人识别（1:N）场景 -> 切换到 InsightFace
- 移动端/嵌入式 -> 考虑 MTCNN + MobileFaceNet

## 二、核心架构与实现

### 2.1 整体链路

```
前端 (Vue3 + WebView2)
  +-- FaceAuthClient.ts：API 通信 + 摄像头操作
  |    +-- getFaceStatus()  -> GET /api/face/status
  |    +-- registerFace()   -> POST /api/face/register  (multipart form)
  |    +-- verifyFace()     -> POST /api/face/verify    (multipart form)
  |    +-- startCamera()    -> getUserMedia + video.play()
  |    +-- captureFrame()   -> canvas 截屏 -> JPEG Blob
  |
  +-- 两种录入方式：摄像头抓拍 / 上传图片（降级方案）

后端 FastAPI (localhost:8000)
  +-- face_recognition.py
       +-- SFaceFaceEngine（单例、懒加载、线程安全）
       |    +-- YuNet (cv2.FaceDetectorYN)：人脸检测 + 5点关键点
       |    +-- SFace (cv2.FaceRecognizerSF)：对齐裁剪 + 128维特征 + L2归一化
       +-- FaceVerificationAdapter：注册/验证逻辑
       |    +-- register_samples()：多张图 -> 提取特征 -> 存 profile
       |    +-- verify()：单张图 -> 提取特征 -> 与 profile 全部样本算余弦 -> 取最大值 vs 阈值
       +-- FaceProfileStore：JSON 文件持久化（128维 float32 base64）
```

### 2.2 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| similarity_threshold | 0.45 | 余弦相似度阈值，>= 则判定为主人 |
| min_samples | 3 | 注册最少样本数，越多越稳，3张是性价比最优 |
| YuNet score_threshold | 0.6 | 人脸检测置信度阈值（默认0.9太严，普通光照会漏检） |
| YuNet input_size | 动态 (宽,高) | 按图片实际尺寸设置，检测更准 |
| 特征维度 | 128 | SFace 输出，L2 归一化后做余弦相似度 |

### 2.3 模型文件

```
backend/models/
+-- face_detection_yunet_2023mar.onnx    (232 KB)  检测模型
+-- face_recognition_sface_2021dec.onnx  (37 MB)   识别模型
+-- face_landmarker.task                 (3.7 MB)  旧版关键点模型（保留备用）
```

下载脚本：backend/scripts/download_face_models.py

## 三、踩坑记录与解决方案（对策卡核心）

### 坑 1：几何关键点无身份区分度

**现象**：用 MediaPipe FaceLandmarker 提取 478 个 3D 关键点归一化后做余弦比对，主人和他人分数几乎一样（间隔 -0.0086），完全无法区分。

**原因**：人脸几何结构在不同人之间差异很小，关键点坐标主要反映姿态和形状，不包含皮肤纹理、五官细节等身份信息。

**对策**：
- **永远先用真实样本标定**，不要靠感觉判断方案行不行
- 1:1 身份验证 -> 直接上专门的 face recognition 模型（SFace / ArcFace / Facenet）
- 几何关键点只适合表情检测、注意力感知、姿态估计等场景

**标定方法**：准备主人 N 张 + 他人 M 张，计算所有组合的余弦相似度，找「主人组最低分 - 他人组最高分」的间隔。

---

### 坑 2：WebView2 中 getUserMedia 静默失败

**现象**：Tauri 打包的桌面应用里，点「录入人脸」后无画面，也没有错误提示。F12 打不开（生产 webview 默认禁用）。

**原因**：WebView2 默认不弹媒体授权对话框，直接拒绝 getUserMedia 请求。前端 catch 到错误后切回 idle 状态，错误信息被隐藏在已消失的面板里。

**对策**（按优先级排序）：

1. **Tauri v2 配置 additionalBrowserArgs**（推荐，最简洁）
   - --use-fake-ui-for-media-stream：自动授予摄像头/麦克风权限
   - 注意必须包含默认的 --disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection，否则会覆盖掉默认值

2. **如果 1 不生效**：通过 with_webview 拿到 ICoreWebView2，注册 PermissionRequested 事件处理器，对摄像头权限自动 allow

3. **前端必加降级方案**：上传图片注册/验证
   - 用户电脑可能没摄像头
   - 摄像头驱动可能有问题
   - 调试时方便快速验证

4. **前端错误信息必须在任何状态下都可见**：
   - 错误示范：错误信息放在 v-else 面板里，失败切回 idle 就看不到了
   - 正确示范：错误信息放在 section 顶层，idle 状态也能看到

---

### 坑 3：按钮因状态加载失败而永久禁用

**现象**：应用启动时人脸状态请求失败（Failed to fetch），faceStatus 为 null，按钮 :disabled="!faceStatus?.configured" 一直为 true，用户连重试的机会都没有。

**原因**：前端页面加载比网关启动快。onMounted 时调 /api/face/status，网关还没起来就失败了，之后没有重试机制。

**对策**：
1. **按钮不要因「状态未加载」就禁用**——能点就点，失败了再报错。禁用只用于「操作进行中（loading）」和「明确无权限」的场景
2. **与网关健康检查联动**：watch(gatewayHealthState)，当网关从 error -> ready 时自动重新加载人脸状态
3. **给用户手动重试的入口**：按钮旁加「重试」或直接让「录入」按钮在失败时也能点（点了先调状态再开摄像头）

---

### 坑 4：人脸验证状态被声纹会话检查清掉

**现象**：人脸验证通过后，身份状态显示「主人已验证」，但过 2-3 秒又变回「未验证」。

**原因**：身份服务是全局单例，声纹验证是「会话制」的（会话结束自动回收权限）。每次调 /api/identity 时检查：如果是 RTC 声纹适配器且没有活动会话，就把 owner_verified 重置为 unknown。人脸验证写入的是同一个 _status，也被一起清掉了。

**对策**：
1. **给 IdentityService 加持久化标记** _persistent_verified
2. **人脸验证用 apply_persistent_verification()** 而非 apply_verification()
3. **声纹会话回收逻辑加判断**：if (not identity.is_persistent) 才重置

---

### 坑 5：CORS 配置只有 http 没有 https

**现象**：开发环境（http://localhost:5174）人脸接口正常，Tauri 打包后（https://tauri.localhost）Failed to fetch。

**原因**：.env 里 CORS_ORIGINS 只配了 http://tauri.localhost，Tauri v2 的 WebView2 用的是 https://tauri.localhost。

**对策**：
1. CORS 配置同时放 http 和 https 两个变体
2. 后端默认值也要包含两者（防止用户没配置时也能工作）
3. 诊断接口返回 CORS 配置（可选，便于排查）

---

### 坑 6：PyInstaller 打包后模型找不到

**现象**：开发环境正常，打包后 /api/face/status 返回 configured: false。

**原因**：模型文件路径解析逻辑只考虑了开发环境的相对路径，没考虑 PyInstaller 打包后 exe 同目录、_internal、_MEIPASS 等多种布局。

**对策**：
- 写一个 face_model_candidates() 函数，按优先级枚举所有可能路径
  1. 配置文件指定的路径（绝对路径直接用，相对路径按 cwd 解析）
  2. 配置目录下的 backend/models/
  3. PyInstaller：exe 同目录 models/
  4. PyInstaller：exe/_internal/models/
  5. PyInstaller：_MEIPASS/models/（onefile 模式）
- 诊断接口 diagnostics.models.*.candidates 列出所有候选路径和存在性，线上排障不用瞎猜
- 打包时把模型文件复制到 exe 同目录的 models/ 下（与开发路径结构一致）

---

### 坑 7：视频元素未就绪（v-if + 同步 ref 时序）

**现象**：点「录入人脸」后报错「视频元素未就绪」，摄像头打不开。

**原因**：点击按钮时先设置 faceMode = "register"，但立刻就读 faceVideoRef.value。Vue 的 DOM 更新是异步的（微任务队列），此时 <video> 元素还没渲染到 DOM 中，ref 还是 null。

**对策**：
1. **设置模式后 await nextTick()**，再操作 DOM 元素
2. **或者用 v-show 代替 v-if**：video 元素一直存在于 DOM，只是隐藏，ref 永远有值
3. 两种方式结合使用更稳

---

### 坑 8：Unicode 路径导致编译/打包失败

**现象**：项目路径含特殊字符（如 Anime-style 中的特殊连字符 U+2011，不是普通 -），npm 命令、Python 导入、cargo 构建各种奇怪错误。

**对策**：
1. Windows 上用 subst 映射到纯 ASCII 盘符再构建
   subst Z: "E:\Anime-style AI Agent Desktop Pet"
2. **所有构建脚本、PyInstaller spec、Tauri 配置都在 Z: 下执行**
3. 输出文件再映射回原路径
4. 项目命名时尽量用纯 ASCII，避免 Unicode 坑

---

### 坑 9：WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS 环境变量不生效

**现象**：在 Rust 代码里 std::env::set_var("WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS", "--use-fake-ui-for-media-stream")，但摄像头还是被拒绝。

**原因**：wry/tauri 创建 WebView2 的时机可能早于 run() 函数中的环境变量设置，或者 wry 新版本不再读取这个环境变量。

**对策**：用 Tauri v2 官方支持的配置项 additionalBrowserArgs（见坑 2 方案 1），不要用环境变量的方式。

## 四、标定与验证方法

### 4.1 样本准备

```
C:\Users\j\Desktop\
+-- 我的人脸样本\         (主人样本，3-5 张正面照)
|   +-- 1.jpg
|   +-- 2.jpg
|   +-- 3.jpg
+-- 他人的人脸样本\       (负样本，5-10 张不同的人)
    +-- a.jpg
    +-- b.jpg
    +-- ...
```

### 4.2 标定脚本

```
python backend/scripts/face_calibration.py \
  --owner "C:\Users\j\Desktop\我的人脸样本\*.jpg" \
  --others "C:\Users\j\Desktop\他人的人脸样本\*.jpg"
```

输出：
- 主人组内相似度分布（min/median/max）
- 他人组内相似度分布（min/median/max）
- **间隔 = 主人组 min - 他人组 max**（正值越大越好）
- 推荐阈值 = (主人组 min + 他人组 max) / 2

### 4.3 验收标准

| 指标 | 合格线 | 说明 |
|------|--------|------|
| 间隔 (gap) | >= 0.2 | 正负样本有明确分界线 |
| 主人通过率 | 100% (3/3) | 所有主人样本都应通过验证 |
| 他人拒绝率 | 100% (5/5) | 所有他人样本都应被拒绝 |
| 阈值安全边际 | >= 0.1 | 阈值到两边的距离都留有余量 |

## 五、打包部署注意事项

### 5.1 网关打包（PyInstaller）

- **单一 spec 文件**：backend/desktop-pet-gateway.spec，不要命令行 --collect-all 乱加
- **模型文件外置**：不放进 datas，由构建脚本复制到 exe 同目录 models/，与开发布局一致
- **精简依赖**：
  - 排除 mediapipe（改用 SFace 后不需要）
  - 排除 matplotlib / pandas / PIL / tkinter / sounddevice
  - 排除 cv2 的 ffmpeg 动态库（图片识别不需要视频编解码，省 29MB）
- **体积参考**：236 MB / 882 文件（SFace 方案）

### 5.2 Tauri 打包

- 前端用 vite build --mode frontend 构建到 dist/
- 网关放在 resources/gateway/（配置在 tauri.conf.json 的 bundle.resources）
- NSIS 安装，installMode: perMachine（装到 Program Files，所有用户可用）
- **CORS 默认值必须包含 https://tauri.localhost**

### 5.3 部署后验证清单

安装完新版本后按以下顺序验证：

- [ ] 应用启动后网关自动启动（进程里能看到 desktop-pet-gateway.exe）
- [ ] /api/health 返回 ok: true
- [ ] /api/face/status 返回 configured: true + 模型路径正确
- [ ] 上传图片注册成功，状态变「已注册」
- [ ] 上传图片验证成功，身份变「主人已验证」
- [ ] **等待 10 秒**，身份状态没有掉回去（验证 persistent 标记）
- [ ] 删除档案后状态恢复「未注册」
- [ ] 上传陌生人照片验证被拒绝
- [ ] 摄像头模式能打开画面（如果设备有摄像头）

## 六、常见问题速查

| 现象 | 可能原因 | 快速排查 |
|------|---------|---------|
| 按钮点不了（灰的） | faceStatus 为 null（网关没起来或 CORS 错） | 看 faceError 红字；F12 看 Network 面板的 /api/face/status |
| 点了没反应 | 摄像头被 WebView2 静默拒绝 | 看错误信息；试上传图片方式是否正常 |
| 验证通过后一会就掉了 | 声纹会话检查清掉了 | 检查后端是否有 persistent 标记逻辑（v0.4.0+ 才有） |
| 注册成功但身份没变 | 注册不等于验证（旧版） | 新版注册后会自动验证一次，旧版需要手动再验证 |
| 提示「模型不存在」 | 模型文件没打包进去 | 看 diagnostics.candidates 里哪条路径是 true |
| 提示「未检测到人脸」 | 照片侧脸/太小/太模糊 | 用正面清晰照；YuNet score_threshold 可适当调低 |

## 七、后续可优化方向

1. **实时视频流验证**：目前是抓一帧发后端，可改成持续比对 + 活体检测
2. **多人支持**：从 1:1 扩展到 1:N，需换更高精度模型（ArcFace）
3. **活体检测**：防止照片欺骗，可加眨眼/摇头动作校验
4. **模型热更新**：模型文件放配置目录，可由用户自行替换升级
5. **Tauri 原生摄像头**：用 Tauri 插件直接调系统摄像头 API，绕开 WebView2 权限问题

# 灵梦桌宠项目说明文档

> 版本 v0.4.0 ｜ Windows 桌面 AI 智能体 ｜ 文档日期：2026-10-20

---

## 1 项目简介

我做的是一个 Windows 桌面 AI 桌宠，用户可以用文字或语音和它对话，它会根据语义切换聆听、思考、说话这些动作，还能调用白名单内的受控工具（查时间、打开应用、放音乐），通过本地人脸识别验证主人身份后解锁长期记忆和高权限工具。技术上是 Tauri + Vue3 前端、FastAPI 本地网关、Godot 渲染，接入豆包流式 ASR、MiniMax TTS 和 Qwen 大模型，RAG 用 Milvus，全部能力走本地网关代理，密钥不下发前端。

整体是四层架构：用户交互层、桌面前端层、本地网关层、云端能力层。一次语音对话的完整链路是：麦克风采集 16kHz PCM → 本地唤醒词/VAD 门控 → 豆包 SAUC 流式识别出文字 → 本地确定性工具规划器判断是否命中明确指令（如"现在几点"）→ 命中就走受控工具秒回，否则连同会话历史、确认记忆、RAG 检索片段一起交给 Qwen，模型按我定义的 JSON Schema 严格输出结构化结果（回复文本、情绪、动作 ID、口型模式、记忆候选）→ MiniMax 合成音频 → 桌宠同步说话动作和口型。关键设计是模型只负责"说话和选动作"，没有任何执行权，所有桌面操作必须过网关的白名单、审批和审计。

## 2 项目背景

### 2.1 需求缘起

源于真实需求：面向想要一个有人设、能语音交互、动作可见的二次元桌面陪伴伙伴的二次元受众；

市面上现有的 AI 陪伴类产品普遍存在四个痛点，构成本项目的直接动机：

1. **"生命感"缺失** —— 多数桌宠只是贴图轮播 + 聊天框，模型回复与角色表演完全脱节；
2. **权限失控** —— 让模型直接执行命令的 Agent 产品，安全完全依赖提示词约束，一次提示注入就可能酿成事故；
3. **隐私让渡** —— 对话记录、声纹/人脸等生物特征、API 密钥全托管在云端，用户失去对数据的控制权；
4. **厂商锁定** —— 前端与单一模型/语音供应商深度耦合，换模型等于重写一遍接入层。

### 2.2 设计原则（针对上述痛点的架构级回应）

| 原则    | 含义                                                    |
| ----- | ----------------------------------------------------- |
| 人格稳定  | 角色语气、称呼、禁忌通过系统提示词与 Persona 配置固化，工程协议永远优先于人设           |
| 本地优先  | 配置、调试历史、工具审批、审计、记忆、人脸特征全部留在本机，密钥不下发前端                 |
| 权限受控  | 模型没有任何执行权，工具必须走白名单、Schema 校验、人工审批与审计四道关               |
| 链路可观测 | ASR / Agent / TTS / 工具 / 身份各环节均有阶段状态、trace_id 与本地历史记录 |
| 可替换服务 | 语音、模型、身份服务均经本地网关适配，换供应商只改环境变量，代码零改动                   |

## 3 核心流程

### 3.1 总体架构（四层）

```
① 用户交互层    语音输入（唤醒词/VAD） · 文本/控制台 · 桌宠视觉反馈
② 桌面前端层    Tauri v2 + Vue3 控制台  ←动作/口型协议→  Godot 4.7 渲染器
③ 本地网关层    FastAPI（REST + WebSocket）· 密钥保管 · Schema 校验 · 审批审计
④ 能力与数据层  豆包ASR / MiniMax TTS / Qwen / 人脸识别（云端经网关代理）
                SQLite（审批·审计·提醒·记忆）· Milvus（RAG）· localStorage（调试历史）
```

前端不直连任何云端服务；所有供应商密钥只存在于服务端 `.env`，由本地网关统一代理调用。

### 3.2 语音对话端到端流程（主链路）

1. **采集门控** —— 麦克风采集 16kHz PCM，唤醒词"小赤红"做本地文本门控（不等同身份认证），VAD 自动断句；
2. **流式识别** —— 豆包 SAUC WebSocket 实时转写，partial/final 事件区分，防重复提交；
3. **意图分流（确定性优先）** —— 本地正则规划器判断是否命中明确指令（"现在几点""打开记事本""播放音乐"）：命中则直接走受控工具，1 秒内返回，不消耗大模型 token；
4. **智能体生成** —— 未命中则组装上下文（会话历史 + 确认记忆 + Persona 人设 + RAG 检索 top-3）交给 Qwen，模型按 JSON Schema 严格输出结构化结果：`text / language / emotion / action_id / mouth_mode / requires_confirmation / memory_candidates`；
5. **安全执行** —— 工具请求经"Pydantic 校验 → 白名单 → 审批（中风险需 10 分钟内人工确认）→ SQLite 审计"四层边界；
6. **语音合成** —— MiniMax TTS 多音色合成，WebAudio 播放；
7. **表演同步** —— 动作 ID 驱动 Godot 状态机切换动作，口型随语音能量实时开合；云端故障时自动降级本地 Mock，聊天不中断。

### 3.3 身份验证与权限流程

```
未验证(unknown) ──人脸注册──▶ 采集人脸（YuNet 检测 + SFace 128 维特征）
                              │
      ┌───────────────────────┴──────────┐
      ▼                                  ▼
 验证通过 → owner_verified          验证失败/陌生人 → guest
 （解锁长期记忆读写、高权限工具，        （仅基础对话，记忆与工具
   但仍不可绕过工具人工审批）             全部禁止）
```

- 人脸特征（SFace 128 维嵌入，L2 归一化）本地存储，原始照片仅在内存中解码、处理后即丢弃，不上传云端；
- 未匹配、低相似度、任务过期等情况一律回落 guest，避免残留旧主人权限；
- 每次身份升降级均写入事件审计。

### 3.4 记忆治理流程

模型在对话中最多提议 3 条记忆候选 → **永不自动保存** → 用户在界面确认后才写入 SQLite → 后续对话作为"事实性上下文（不可执行指令）"注入 → 用户可随时编辑或彻底删除；密钥、卡号、证件号等敏感内容在入库前即被正则拦截。短期记忆则采用进程内有界上下文（默认 6 轮），重启即清。

## 4 项目亮点

### 4.1 模型无执行权的四层安全边界

大模型只能"说话 + 从枚举中选动作 + 提议记忆"，一切桌面操作由网关侧受控工具服务代为执行：**前端只调网关 → Pydantic Schema 校验 → 白名单与审批策略 → 执行写审计**。高风险工具默认关闭，主人身份也不能绕过人工审批——从架构上杜绝提示注入导致越权的可能。

### 4.2 结构化输出驱动的"表演系统"

模型响应被 JSON Schema 严格约束为包含情绪、动作、口型的结构化对象，一次响应同时驱动对话 UI、Godot 动作状态机与口型能量同步——**回答即演出**，这是与"贴图轮播式"桌宠的本质区别。

### 4.3 用户确认制的记忆治理

记忆的"提议权"在模型、"决定权"在用户：候选制 + 敏感信息拦截 + 可编辑可删除 + 短长期记忆严格隔离，兼顾个性化体验与数据安全。

### 4.4 完全离线的本地人脸身份

OpenCV YuNet 人脸检测 + SFace 128 维身份嵌入 + 本地余弦比对（阈值 0.45，≥3 张样本注册），全程无云端参与；档案只落特征向量、不存原图。配套身份适配器协议，验证方案可整体替换而权限体系零改动（已由声纹→人脸、MediaPipe 关键点→SFace 两次真实迁移验证）。

### 4.5 中 / 日 / 英三语语音全链路

唤醒词门控、VAD 断句、流式识别、确定性意图分流、多音色合成、口型同步——三种语言均完成真实云端接口的端到端验收；明确指令走本地规则实现秒级响应。

### 4.6 工程化交付与可观测性

263 个单元测试 + 非破坏性 E2E 验收脚本 + 一键 MSI 打包（升级不覆盖用户配置）；全链路阶段状态、trace_id 与本地调试历史让每次对话的每一环都可定位、可回溯；云端服务故障时自动降级，聊天能力永不中断。
